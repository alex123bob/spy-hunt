# Clans Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Registered players form clans whose finished games and daily puzzles score points in weekly seasons against a rival clan.

**Architecture:** A new backend module `clans.py` owns membership, points, weekly rollover and pairing, all in SQLite and all lazy (no scheduler). Point awards hook into `game._finish` and the daily-puzzle completion in the same transaction. The frontend adds a `/clan` screen, a top-bar entry, and a badge on players.

**Tech Stack:** Backend: Flask, SQLite, pytest (`ai_svc/spy_hunt`, repo `/Users/jiali/personal_github_repos/PP-AI-Service`). Frontend: React 19, TypeScript, vitest, Playwright (repo `/Users/jiali/personal_github_repos/spy-hunt`).

**Spec:** `docs/superpowers/specs/2026-11-11-clans-design.md` (frontend repo). Read it first; its "Calls added after the builder check" section is binding.

## Global Constraints

- Clan name 3-20 chars, unique case-insensitively; max 30 members; one clan per account; registered accounts only (guests get 403 `register_required`).
- Points: game = 10 taking part + 10 if on the winning side; daily = 10 finished + 10 solved; cap 100 per player per UTC day; 0 for rooms with fewer than 2 human players and for games with `winner` None.
- Season = Monday 00:00 to Sunday 24:00 UTC. Rival needs >= 3 members and points last week. Odd one out faces a "ghost" scoring the average of this week's other clans, floored at 50.
- Draw leaves the win streak unchanged; a loss resets it to 0. History shows the last 8 weeks.
- Leaver's points stay in the clan; leader succession by earliest `joined_at`; last member leaving deletes the clan.
- Schema changes are additive and idempotent in `init_db()`. `player_id`, token format and existing responses stay compatible (new fields only).
- Rate limits reuse the `action` and `read` scopes. i18n keys in both `en.json` and `zh-Hans.json`.
- Backend deploys before frontend. Trunk is `main` in both repos; work in a worktree.

## Review Focus

- Retried `_finish` or a repeated daily completion must not double-award points (idempotency key per game `room_id:game_no` and per `day`).
- A player in no clan, or a guest, finishing a game must be unaffected (no error, no row).
- Two concurrent joins to a clan with 29 members must not exceed 30.
- First request after a week boundary with no traffic for several weeks must close each missed week once, not repeatedly or never.
- A user leaving then creating or joining another clan mid-week: old points stay with the old clan, new points go to the new one.
